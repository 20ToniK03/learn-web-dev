# Тестирование. Задание 3. Классы эквивалентности, граничные значения и таблица решений

Объект тестирования: учебное приложение салона ÉLAIRE, экран «Подтверждение записи».
Поля: «Номер телефона» и «Ваше имя».

## 3.1. Классы эквивалентности и граничные значения

### Требования к полям

- «Номер телефона»: российский мобильный номер в формате +7 (XXX) XXX-XX-XX, 11 цифр, начинается с +7.
- «Ваше имя»: только буквы кириллицы, от 2 до 40 символов.

| Класс | Тип | Описание | Пример значения |
|---|---|---|---|
| P1 | Валидный | 11 цифр, начинается с +7, мобильный код 9XX, формат +7 (XXX) XXX-XX-XX | +7 (999) 123-45-67 |
| P2 | Невалидный | Пустое значение или только пробелы | (пусто) |
| P3 | Невалидный | Меньше 11 цифр | +7 (999) 123-45-6 |
| P4 | Невалидный | Больше 11 цифр | +7 (999) 123-45-678 |
| P5 | Невалидный | Не начинается с +7 | 8 (999) 123-45-67 |
| P6 | Невалидный | Буквы и посторонние символы | +7 (999) ABC-45-67 |
| P7 | Невалидный | Код не мобильного диапазона 9XX | +7 (495) 123-45-67 |

### Классы эквивалентности для поля «Ваше имя»

| Класс | Тип | Описание | Пример значения |
|---|---|---|---|
| N1 | Валидный | От 2 до 40 символов, только кириллица | Анна |

### Уточнение по требованию к имени

Требование «только буквы кириллицы» не описывает пробел и дефис. Формально имя «Анна Петрова» содержит пробел и не должно проходить проверку, но именно такой пример указан в placeholder поля. Нужно уточнить у проектировщика, разрешены ли пробел и дефис как разделители частей имени. В текущих тестах основной валидный класс N1 содержит одно слово из кириллицы. Если пробел и дефис разрешат, добавится класс N6 «кириллица с пробелом или дефисом».

### Фактическое поведение текущей сборки

Проверка полей на клиенте отсутствует. Все значения из таблиц, включая пустые, короткие, длинные и с буквами, принимаются, форма отправляется, модальное окно «Запись подтверждена» открывается. Это подтверждает дефекты BUG-01 и BUG-02 из задания 2 и задания 4.

## 3.2. Таблица решений для шага «Подтверждение записи»

### Условия

- C1: поле «Ваше имя» заполнено.
- C2: поле «Номер телефона» заполнено.
- C3: номер телефона валиден по требованиям из 3.1.

Запись подтверждается только тогда, когда все три условия истинны.

### Полная таблица решений

| Правило | C1: Имя заполнено | C2: Телефон заполнен | C3: Телефон валиден | Ожидаемый результат |
|---|---|---|---|---|
| R1 | Да | Да | Да | Запись подтверждается, открывается модальное окно «Запись подтверждена» |
| R2 | Да | Да | Нет | Запись не подтверждается, ошибка «Некорректный номер телефона» |
| R3 | Да | Нет | Да | Комбинация невозможна: пустой телефон не может быть валидным. Ожидается ошибка «Укажите номер телефона» |
| R4 | Да | Нет | Нет | Запись не подтверждается, ошибка «Укажите номер телефона» |
| R5 | Нет | Да | Да | Запись не подтверждается, ошибка «Укажите имя» |
| R6 | Нет | Да | Нет | Запись не подтверждается, ошибки «Укажите имя» и «Некорректный номер телефона» |
| R7 | Нет | Нет | Да | Комбинация невозможна: пустой телефон не может быть валидным. Ожидаются ошибки «Укажите имя» и «Укажите номер телефона» |
| R8 | Нет | Нет | Нет | Запись не подтверждается, ошибки «Укажите имя» и «Укажите номер телефона» |

### Сокращённая таблица решений

| Правило | C1 | C2 | C3 | Ожидаемый результат |
|---|---|---|---|---|
| R1 | 1 | 1 | 1 | Подтвердить запись |
| R2 | 1 | 1 | 0 | Ошибка валидации телефона |
| R3 | 1 | 0 | - | Ошибка «Укажите номер телефона» |
| R4 | 0 | 1 | 1 | Ошибка «Укажите имя» |
| R5 | 0 | 1 | 0 | Ошибки имени и телефона |
| R6 | 0 | 0 | - | Ошибки имени и телефона |

Обозначения: 1 - условие истинно, 0 - условие ложно, «-» - условие не имеет значения, потому что телефон не заполнен.

### Фактическое поведение текущей сборки

В текущей версии все восемь комбинаций приводят к подтверждению записи: проверки C1, C2 и C3 не реализованы. Это нарушает ожидаемые результаты R2-R8 и подтверждает дефекты BUG-01 и BUG-02.
