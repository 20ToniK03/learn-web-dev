# Тестирование. Задание 1. Пользовательский сценарий и функциональные требования

Объект тестирования: учебное приложение салона ÉLAIRE (React + Vite, имитационный сервер).
Сценарий: клиент записывается на услугу.

## 1. Happy path: клиент записывается на услугу

Сценарий разбит на шаги и подшаги. В скобках указано, что в этот момент видит клиент.

- **Клиент записывается на услугу**
  - **1.1. Открыть каталог услуг**
    - **1.1.1.** Открыть главную страницу приложения (видит заголовок «Запланируйте время для себя» и кнопки «Записаться на услугу», «Выбрать мастера»)
    - **1.1.2.** Нажать «Записаться на услугу» (открывается экран «Выбор услуги»)
    - **1.1.3.** Дождаться загрузки категорий (видит сайдбар с категориями и заглушку «Загрузка категорий...» до ответа сервера)
  - **1.2. Выбрать услугу**
    - **1.2.1.** Выбрать категорию в сайдбаре, например «Маникюр и педикюр» (категория подсвечивается, справа загружается список услуг)
    - **1.2.2.** Дождаться загрузки списка услуг (видит название, описание, длительность, цену и кнопку «Выбрать» у каждой услуги)
    - **1.2.3.** Нажать «Выбрать» у нужной услуги, например «Японский эстетический маникюр P.Shine» (открывается экран «Выбор даты и времени»)
  - **1.3. Выбрать дату и время**
    - **1.3.1.** Дождаться загрузки календаря (видит месяц и год, прошедшие дни заблокированы)
    - **1.3.2.** Выбрать доступный день, например 17 октября 2026 (день подсвечивается, загружаются слоты)
    - **1.3.3.** Дождаться загрузки слотов (видит доступные и занятые слоты, занятые нельзя выбрать)
    - **1.3.4.** Выбрать доступное время, например 12:00 (слот подсвечивается, время появляется в нижней панели)
    - **1.3.5.** Нажать «Далее» (открывается экран «Подтверждение записи»)
  - **1.4. Подтвердить запись**
    - **1.4.1.** Проверить детали визита (услуга, дата и время, мастер, длительность, цена)
    - **1.4.2.** Ввести имя в поле «Ваше имя»
    - **1.4.3.** Ввести номер телефона в поле «Номер телефона»
    - **1.4.4.** При необходимости ввести комментарий к записи
    - **1.4.5.** Нажать «Подтвердить запись» (кнопка меняется на «Отправка...», поля блокируются)
    - **1.4.6.** Дождаться ответа сервера (запись сохраняется в server/bookings.txt)
  - **1.5. Завершить запись**
    - **1.5.1.** Увидеть модальное окно «Запись подтверждена» с деталями визита
    - **1.5.2.** Нажать «Отлично!» (модальное окно закрывается)
    - **1.5.3.** Вернуться на главную страницу (данные записи сбрасываются)

## 2. Функциональные требования

Требования сгруппированы по трём экранам записи. Формулировка по шаблону
«Система должна [действие], когда [условие]».

### 2.1. Экран «Выбор услуги»

| ID | Требование |
|---|---|
| REQ-01 | Система должна отображать список категорий услуг, когда клиент открывает экран выбора услуги. |
| REQ-02 | Система должна автоматически выбирать первую категорию, когда список категорий успешно загружен. |
| REQ-03 | Система должна отображать список услуг выбранной категории с названием, описанием, длительностью и ценой, когда клиент выбирает категорию. |
| REQ-04 | Система должна переходить к выбору даты и времени, когда клиент нажимает «Выбрать» у услуги. |

### 2.2. Экран «Выбор даты и времени»

| ID | Требование |
|---|---|
| REQ-05 | Система должна отображать календарь текущего месяца и блокировать прошедшие даты, когда клиент открывает экран выбора даты и времени. |
| REQ-06 | Система должна отображать доступные и занятые слоты, когда клиент выбирает день в календаре. |
| REQ-07 | Система должна сбрасывать выбранное время, когда клиент меняет день. |
| REQ-08 | Система должна показывать предупреждение «Пожалуйста, выберите время» и не переходить дальше, когда клиент нажимает «Далее» без выбранного времени. |
| REQ-09 | Система должна переходить на экран подтверждения, когда клиент выбирает доступное время и нажимает «Далее». |

### 2.3. Экран «Подтверждение записи»

| ID | Требование |
|---|---|
| REQ-10 | Система должна отображать услугу, дату, время, мастера, длительность и цену, когда клиент открывает экран подтверждения. |
| REQ-11 | Система должна отправлять запись на сервер, когда клиент нажимает «Подтвердить запись». |
| REQ-12 | Система должна показывать модальное окно «Запись подтверждена» и возвращать на главную, когда сервер успешно сохранил запись. |

## 3. Проверка полноты

- Сценарий покрывает все три экрана записи и возврат на главную.
- В сценарии есть точки, где поведение зависит от данных: выбор категории, выбор дня, выбор слота.
- Требования покрывают загрузку данных, выбор, переходы между экранами, отправку формы и успешное завершение.
- Негативные сценарии, валидация полей и обработка ошибок описаны в заданиях 2 и 3.
